# Search Ladder

> 检索阶梯：从最强、最便宜的键开始，每一步都有停止条件。
> 目标不是“搜得多”，而是“用最少的调用，拿到可分级的事实”。

## 0. 原则

1. **强键优先**：DOI、ORCID、论文题名、导师+机构、官方名单。
2. **每一步先问“这一步能新增什么唯一信息”**；不能，就跳下一步或停。
3. **每条结果标 A/B/C/D**；推断和事实分开。
4. **同一意图 3 次无新增唯一信息 → 停**，不要换同义词硬搜。

## 1. 论文 → DOI → ORCID API（首选）

### 做法

```text
https://pub.orcid.org/v3.0/expanded-search/?q=digital-object-ids:"<DOI>"
```

多个 DOI 可以逐个查；不要一次拼太多。

### 为什么

- 实践中最短路径：一个 DOI 就能直接定位作者 ORCID。
- 对比：出版社文章页常不暴露 ORCID；Crossref 的 `author[].orcid` 可能全为 null；ORCID 姓名+单位搜索常漏检。
- OpenAlex 的 `authorships[].author.orcid` 不可靠：实践中有错配，也有 null。

### 作者 ID 污染

- **OpenAlex** 可能给同一位作者的不同论文标不同 ORCID（实践中见过同一作者多篇论文被标多个不同 ORCID，均为他人）。
- **Semantic Scholar** 可能把同名作者的论文合并（实践中见过大量他人论文被合并到同名作者）。
- 结论：OpenAlex / Semantic Scholar 只用于“发现论文/机构”，**不做最终身份**；DOI→ORCID API 才是主路径。

### 解析

返回 JSON 里找 `expanded-result`，逐条取：

- `orcid-id`
- `given-names` / `family-names`
- `institution-name`
- 若有多条，按姓名+单位+论文题名筛选，不要拿第一条。

**一篇论文会返回所有作者的 ORCID**：实践中见过一篇论文返回多条（全部作者）；必须按姓名筛，不能拿第一条。

### 失败时

- 无结果 → 进入第 3 步（学校官网）或第 5 步（问用户）。
- API 限流 → 等 1–2 秒重试 1 次；仍失败就换路线。

### 脚本

```bash
python scripts/orcid_by_doi.py 10.0000/example.2025.000001
python scripts/orcid_by_doi.py 10.0000/example.2025.000001 --json
```

## 2. ORCID → Education

### 做法

打开 `https://orcid.org/<orcid-id>`，读 `Education and qualifications`。

### 注意

- ORCID 的 Education 是**作者自填**，标 B，不是 A。
- **如果 Education 为空，不要推断本科**；用论文 affiliation + 学校官网/用户锚点。
- 实践案例：某 ORCID 只有 1 篇 works，没有 Education/employment；只能确认“论文 + 单位 + 合作者”，不能推断本科。下一步要本科页面/学位论文/导师。
- ORCID 页常有 **Scopus Author ID**；可以作为出版社/Scopus 侧的桥。
- ORCID 页的 Works 列表可以用来核对论文清单；如果某篇论文不在名下，可能是同名另一人。

## 3. 本科院校官网

### 入口

- 优秀毕业生事迹
- 推免 / 拟录取公示（只对已通过门槛的公开学者，作 C/D 时间线佐证；**不作为检索入口**）
- 学院新闻 / 科研招募 / 课题组新闻
- 导师主页 / 师资页

### 检索式示例

```text
site:<本科院校域名> <姓名>
"<姓名>" "<导师>" <学校> <学院>
<学校> <年份> 推荐免试 硕士研究生 拟录取名单 <学院>
```

### 来源级别

- 能抓到学院官网原件 / PDF → A。
- 只抓到搜索摘要 / 二手转载 → B。
- `.edu.cn` 页面经常隧道错误 / 引擎失败：重试 2 次，失败就降级为摘要并标 B；不要死磕。

### 常见坑

- `firecrawl` 对部分高校页面会 `ERR_TUNNEL_CONNECTION_FAILED` 或“All scraping engines failed”；此时只有搜索摘要可用。
- 学院站内搜索经常没有索引；不要把它当唯一入口。

## 3a. 导师佐证（论文通讯作者只是 D）

- 论文的通讯作者/末位作者只是**推断（D）**，不能直接写“导师”。
- 再搜 `"导师名" + 学院 + 科研招募/课题组`，找学院官方页或导师主页；A 需 3 点吻合（姓名 + 至少 2 个独立佐证），只有姓名 = B/待核。
- **定向搜学院“科研招募”栏目**：`site:<学院域名> 科研招募 <导师名>`；找含“指导教师/负责人”的页面。
- **级别规则**：有“学生—导师”直接页面且 3 点吻合 → A；只有姓名 = B/待核；只有课题组页/通讯作者 → B；只有论文末位作者 → D。
- 实践教训：一次 eval 中，with-skill 只找到课题组页，导师标 B；baseline 找到了“科研招募”页，但多花了约 2 倍调用/token。定向搜索这一步要补。

## 3b. 导师反查：学院名录 → 教师主页 → 学生信息

### 适用条件

- 已知：学院、专业/方向（或至少入学年份）、一篇论文/一个研究主题；
- 未知：导师；
- 学院有公开师资页，学校有教师主页系统（或有课题组/团队成员页）。

### 做法

1. **拉学院师资名录**：学院官网“师资队伍/导师名录”逐系拉全；记录姓名、职称、硕导/博导、研究方向。
2. **确认专业/方向**：找该入学年份的硕士招生专业目录（学校研招网/学院研究生招生页），确认学院下有哪些专业，不要把“学院”当“专业”。
3. **按方向筛候选**：用目标论文主题/研究方向 × 导师研究方向做第一轮；保留 5–8 个候选，不要只留 1 个。
4. **查教师主页的“学生信息”栏**：
   - 学院官网的个人简介通常**不列学生**；要另找学校教师主页系统（如 `faculty.<学校域名>`）。
   - 先搜 `site:faculty.<学校域名> "<姓名>"`；不行再试 `"<姓名>" "教师主页" "<学院>"`；再不行猜拼音 URL（`https://faculty.<学校域名>/<pinyin>/zh_CN/index.htm`）。
   - 在个人主页找 `学生信息` / `课题组成员` / `科研团队` / `团队` 栏。直接列出目标姓名 + 3 点吻合（姓名 + 至少 2 个独立佐证：学院/学位/年级/论文主题）= **A 级**；只有姓名 = **B/待核**。
5. **组内方向吻合检查**：导师公开研究方向 + 课题组公开研究主题（聚合层面）+ 目标论文主题；仅方向吻合 = **D**，方向吻合 + 官方导师主页/课题组页 = **B 级支持**，不单独当身份确认。
6. **多候选交叉**：哪个候选的学生栏出现目标姓名且 3 点吻合，哪个就是 A 级；只有姓名 = B/待核；若都没出现，写“不作为支持/降低候选优先级/待核”，不要写“排除”，也不要硬指认。

### 检索式示例

```text
site:<学院域名> 师资队伍
site:faculty.<学校域名> "<姓名>"
"<姓名>" "教师主页" "<学院>"
"<学院>" "<入学年份>" 硕士研究生 招生专业目录
```

### 级别规则

- 教师主页“学生信息”栏直接列名，且 3 点吻合（姓名 + 至少 2 个独立佐证：学院/学位/年级/论文主题） → **A**（页面自维护，但属学校官方系统）。
- 只有姓名、没有第二/第三点 → **B/待核**，不能写“确认”。
- 只有“科研团队/课题组成员”页、没有学生姓名 → **B**。
- 只有方向吻合、没有名单 → **D**；方向吻合 + 官方导师主页/课题组页 = **B 级支持**。
- 学院官网个人简介不列学生 → 不能拿它当“没有导师关系”的证据。

### 关键坑

- **“学生信息”常只列“在读”**：已毕业、延毕、页面未更新都会漏；缺席只降低候选优先级，不能单独当排除证据。只有“页面名单完整 + 对目标入学年份有效 + 至少两个独立负面检查”同时成立，才可写 **排除**。
- **不是每个老师都填这一栏**：没写不代表没有学生；换课题组页/学院新闻/由人提供的公众号文章；**不自动化微信搜一搜**。
- **页面自维护**：可能滞后；至少 3 点吻合（姓名 + 至少 2 个独立佐证：学院/学位/年级/论文主题）才写 A；只有姓名写 B/待核。
- **“独立佐证”口径**：学院不得仅由页面所属推断；学位与年级不得由同一行/同一字段同时充当两个佐证；论文主题须来自目标论文。
- **同名风险**：学生栏出现同名时，用学院/专业/年级/论文再核；不要只凭姓名。
- **隐私边界**：学生名单只用于核验导师关系，不扩展为私人档案；不记录、不比较、不输出其他学生姓名/方向，不抓联系方式、毕业去向、家庭信息。

### 已验证案例（去标识化）

- 目标：某高校某学院研究生，有 1 篇公开论文（DOI 已隐去），署名单位为该学院。
- 学院师资页 → 按论文主题/研究方向筛出一组候选（不要只留 1 个）。
- 学校教师主页 `faculty.<域名>` → 某候选导师的“学生信息”栏直接列出目标姓名，且 3 点吻合（姓名 + 至少 2 个独立佐证：学院/学位/年级/论文主题） → **A 级**。
- 对照：其他候选的学生栏名单中没有目标姓名 → **不作为支持/降低候选优先级**（页面可能只列在读，不写“排除”）。
- 该导师方向与论文主题吻合，且有官方导师主页/课题组页佐证 → **B 级支持**。
- 教训：**先找教师主页系统，不要只在学院简介页找学生名单；A 级来自“学生信息”栏直接列名且 3 点吻合，不是方向吻合。**

## 4. 两端名单交叉（只在 ORCID 缺失时）

### 做法

1. 确定两端：某年进 A 校 A 学院（硕士/推免）；某年进 B 校 B 学院（博士/拟录取）。
2. 拉两端官方名单（研究生院 / 学院官网 / Wayback）。
3. **先抓样本确认表头**：有没有“推荐单位 / 本科学校”？有没有考生号/学号？
4. 统计同名数；按姓名 + 专业 + 年份 +（如有）唯一标识做交集。
5. 输出标 **C 级**，除非有唯一标识。

### 实践教训

- 某高校推免名单现网 404；经二手页的原始附件直链找到 Wayback 多页快照。
- 该名单表头**只有学院/专业/姓名/备注，没有“推荐单位”**。
- 全名单同名多人；另一端 PDF 无院校字段。
- 交集只能说明“时间线吻合、专业邻近”，不能说明“就是同一个人”。
- **“综合考核名单” ≠ “拟录取名单”**，混用会得出错误结论。

### 结论

名单交叉是“缩小候选 / 时间线一致性检查”，不是身份确认。不要假设名单有推荐单位；不要把它当 ORCID 的替代。

## 5. 向用户要锚点

卡住时，不要继续换关键词。直接要一个强键：

- “你方便发一下她的 ORCID 吗？”
- “你看到的那篇公众号/学院页面链接能发我吗？”
- “你知道她的导师/课题组吗？”
- “你有没有论文 DOI 或题名？”

**不要**说“再搜搜”；要给具体的东西。

## 工具路由

| 任务 | 首选 | 备注 |
|---|---|---|
| 中文查询 | `search-failover` | bocha 失败时换 tavily；记录 provider |
| 官方页 / PDF | `firecrawl_scrape` | `.edu.cn` 可能失败；失败后试 Playwright |
| 英文论文 | OpenAlex / PubMed / Crossref | 必须 `select` / `per_page` / `filter` |
| 中文论文 | CNKI | 只覆盖中文库 |
| 导师/学生名单 | 学校教师主页系统（`faculty.<学校域名>`） | 学院官网简介通常不列学生；先搜 `site:faculty.<域名> "<姓名>"` |
| ORCID | DOI 查询 `digital-object-ids` | 不要先按姓名+单位 |
| ScienceDirect | 只查正文 author-group | 不要全文 grep “orcid” |
| 微信 | `wechat read`（人给链接） | **不自动化搜一搜** |
| 大响应 | 本地脚本 | 先落盘，再过滤 |

## 失败模式

| 现象 | 原因 | 对策 |
|---|---|---|
| OpenAlex ORCID 错配 / null | 聚合元数据不可靠 | 改用 DOI → ORCID API |
| Crossref `author[].orcid` 全 null | 出版商没填 | 不要在这里死磕 |
| ScienceDirect 没有 ORCID | 作者页不暴露 | 不要 grep 全文；走 DOI→ORCID |
| `.edu.cn` 隧道错误 | 网络 / 反爬 | 重试 2 次；降级摘要标 B |
| 名单 404 | 公示过期 | 试 1 次 Wayback；换入口 |
| 名单没有推荐单位 | 表头差异 | 用 ORCID / 学校官网补 |
| 教师主页无“学生信息”栏 | 未填/未上线 | 换课题组页/学院新闻/由人提供的公众号文章；不自动化微信搜一搜；缺席只降低优先级 |
| 同名很多 | 中文高重名 | 先统计同名数；加第二键 |
| “综合考核名单”当“拟录取” | 名单类型混淆 | 看清标题和公示期 |

## 停止规则

- 同一意图 3 次无新增唯一信息 → 停。
- 404 最多 1 次 Wayback。
- 连续 2 个假阳性 → 回到强键。
- 单次抓取 >10 万字符 → 落盘 + 过滤。
- 用户说“只给链接” → 切 `links-only`。

## Replay 证据（去标识化）

| 路径 | 调用 | 结果 |
|---|---|---|
| ORCID-first | 16 次网络调用 | ORCID 页 1 次命中；本科院校页搜索命中但原件抓取失败；博士名单 PDF 命中 |
| paper → ORCID | 9 次抓取 | DOI→ORCID API 两篇一次命中；出版社/Crossref/姓名搜索都不行 |
| 两端名单 | 37 次 | 两端名单都拿到；无推荐单位；同名多人；交集 C 级 |
| 原始会话 | 83 次 | 本科结论“公开渠道查不到”，最后由人补位 |

**一句话**：不是“搜得多”赢，是“先强键、再分级、会停”赢。
